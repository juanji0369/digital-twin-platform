## 配置发布与同步

前端在本地编辑完整网关配置，保存时将完整集合提交为 App 草稿，发布时由 App 比较草稿及已发布配置，仅保存实际变化并更新受影响版本。App 提交发布事务后，通知 Gateway 最新配置版本。
前端提示空通信配置，App 发布时拒绝任一功能列表为空的通信配置并校验配置完整性；Gateway 直接解析和应用已发布配置。新增功能 ID 由前端随机生成，App 校验非空及同设备内唯一，同设备内迁移通信配置复用 ID。
网关连接可用时，App 等待 ConfigVersionResp 确认通知已接收；发送失败或等待超时后重发当前最新版本通知，收到匹配 requestId 的成功响应或网关离线时结束等待。
Gateway 携带本地生效版本请求配置，App 返回更新项和忽略列表，Gateway 合并后保存并应用。
获取配置或准备候选配置期间收到更新版本通知时，Gateway 使当前配置请求失效，忽略其响应及准备结果，以新的 requestId 携带当前生效版本重新请求。进入落库与运行时应用后完成当前轮，再处理最新待同步版本。

Gateway 进程重启按已持久化配置及版本初始化，设备连接失败照常进入连接状态，继续连接恢复与采集，不等待 App 同步完成。无本地配置时从版本 0 请求，App 尚无配置时返回同版本 0 的无增量 ConfigResp，首次发布配置使用版本 1。
每个合法 ConfigReq 均返回 ConfigResp。版本相等时返回无增量响应并保持运行时；本地版本较低时合并更新；本地版本超前时记录异常并接受 App 全量配置。配置解析与运行时应用完成、连接状态更新后，快照内容变化交给统一节流，不等待全部连接成功。
后台持续重连和同步。离线期间的配置变化通过接入同步获取。

## 采集与上报

Gateway 周期上报最新记录，并按 storeHistory 保存采集历史，具体规则见[采集与周期上报](./gateway.md#采集与周期上报)。
Gateway 按运行编排、业务和基础三层组织，模块通过明确入口直接调用。采集管理将结果交给数据管理，数据管理更新周期缓存并按采集时的 storeHistory 筛选历史交给存储缓存；连接及存储结果更新状态管理。状态上报完成后，将附带上报结果的状态历史交给存储缓存。存储缓存按上报间隔统一消费两类有界队列，在 DuckDB 中分表批量提交，网络发送由 Task 执行。
周期批次失败后释放，下一周期发送新缓存中的记录。历史写入与周期上报并行，已入队和已入库数据保持采集时规则；配置变更后的在途结果按功能 ID 和时间更新最新读数，不按当前通信归属过滤。

Gateway 通过 StatusReportReq 统一上报生效配置中的设备、连接、功能总数及全部 UNKNOWN 或异常连接及两个数据库的当前状态。内容变化统一节流，流就绪时补当前完整快照，触发与调度规则见 [Gateway 状态维护与上报](./gateway.md#状态维护与上报)；每个快照仅尝试发送一次。状态历史保存快照异常部分，以快照生成时间 occurredAt 为时间轴，上报成功或失败为附带属性；上报结束后交给存储缓存，状态变化不直接入库，失败快照不补发。队列满时淘汰较早的未发送快照。
App 将接收的状态事件和去重标记提交后返回 ReportResp；按网关、快照生成时间及内容识别重复快照。App 通过 StatusHistoryReq 代理查询网关本地状态历史，按 occurredAt 过滤及排序，将结果直接返回前端，离线及超时返回明确错误。周期 ReportReq 单向发送，App 更新功能最新记录。

App 在内存维护查询视图，并向前端推送最新记录和状态变化。App 无当前记录时保存，仅在采集时间戳更大时更新已有记录，相同或更小时间戳不更新。功能当前结果仅保留正常值或异常 code，并记录采集时间和上报时间。历史查询通过双向流转发给对应 Gateway。

## 数据归属

| 数据 | 保存位置 |
| --- | --- |
| 配置草稿与已发布配置 | App SQLite |
| 生效配置及版本 | Gateway SQLite |
| 启用入库的采集历史 | Gateway DuckDB + Parquet，默认保留 7 天 |
| 网关状态变动历史、附带的上报结果 | Gateway DuckDB + Parquet，与采集历史分表保存 |
| 网关上报、App 用户操作及报错事件 | App DuckDB + Parquet |
| 当前会话、运行状态、功能最新记录 | App 进程内存 |
| 运行诊断 | App 结构化日志；Gateway 标准错误输出 |

事件库记录网关上报，以及 App 本地用户操作和报错事件；诊断输出提供排障信息。
一次操作可以同时产生业务事件和诊断日志。

## 连接与状态

Gateway 每次认证 gRPC 双向流就绪时补当前完整状态快照，并携带本地生效版本请求配置。已有连接继续运行，受影响连接按新配置建立，后续内容变化触发统一节流。

| 对象 | Gateway 职责 | App 职责 |
| --- | --- | --- |
| 功能读数 | 采集并通过 ReportReq 上报互斥的 value/code | 保存最新记录，派生 ok/error/unknown |
| 连接问题 | 按 deviceId、communicationId 维护 UNKNOWN 或异常状态，通过 StatusReportReq 上报完整 connectionIssues | 保存问题索引，按设备展示具体连接问题 |
| 网关运行 | 维护非正常连接及存储状态，通过 StatusReportReq 上报 | 保存网关运行视图 |
| 网关与平台连接 | 建立并维护双向流 | 根据流生命周期维护 online/offline/unknown |

功能是最小数据单位，按 gatewayId、deviceId、propertyId 匹配当前配置。无记录为 unknown，最新 value 为 ok，最新 code 为 error。连接异常及恢复保持功能记录和时间；设备作为连接的归属和查询入口，各通信配置的问题分别展示。
storage 始终包含配置库、业务数据库的 status 和 timestamp，业务数据库沿用 collectionDatabase 字段，涵盖采集历史及状态变动历史；status 为 UNKNOWN、OK 或异常语义码。connectionIssues 包含全部 UNKNOWN 或异常连接，均携带状态开始时间，确认正常后移除。相同状态重复确认保持时间戳不变。列表为空表示快照对应配置中的连接均已确认正常；MQTT 的连接情况反映到外部 broker 的通道可用性，不能证明发布设备在线。
App 从内存提供查询并通过 WebSocket 推送变化，消息与订阅协议见[App 前端接口](./api.md#websocket-实时订阅)，页面订阅及重连流程见[前端设计](./frontend.md#websocket-使用)。

时间使用 Unix 毫秒，间隔和超时使用毫秒。采集时间取结果到达 Gateway 的时间，上报时间取发送时间，接收和入库时间由处理进程记录。
主机启用系统时间同步。业务字段使用 camelCase，Protobuf 和持久化字段使用 snake_case。
